Unidad 6 · Tema 6.3

Funciones del sistema de protección

Una política sirve cuando el sistema puede aplicarla. El sistema operativo convierte las reglas de acceso en decisiones y mecanismos.

Tema 3 de 7Fuentes de este tema
Idea central

El sistema de protección controla las operaciones que los procesos pueden realizar sobre los recursos. Su trabajo es aplicar la política de acceso y mantener las fronteras de aislamiento.

Funciones principales

  • Aislar: separar procesos, espacios de memoria y componentes privilegiados para limitar interferencias.
  • Mediar: ofrecer rutas controladas, como llamadas al sistema, para solicitar acceso a archivos y dispositivos.
  • Autorizar: comprobar si la identidad y el contexto del proceso satisfacen los permisos requeridos.
  • Administrar derechos: permitir conceder, modificar y revocar autorizaciones de manera controlada.
  • Registrar: conservar eventos relevantes para auditoría, detección e investigación.

Estas funciones se apoyan en hardware y software. Por ejemplo, la CPU distingue niveles de privilegio, mientras el sistema operativo configura la memoria y mantiene las estructuras de permisos.

Tres piezas de una solicitud

Sujeto

Entidad activa que solicita una operación: un usuario o un proceso que actúa bajo una identidad.

El proceso del editor que usa el estudiante.

Objeto

Recurso sobre el que se actúa: archivo, dispositivo, región de memoria o servicio.

El archivo Calificaciones.csv.

Derecho

Operación autorizada sobre el objeto, como leer, escribir o ejecutar.

Lectura permitida; escritura restringida.

Un dominio de protección es el conjunto de objetos y derechos al que puede acceder un proceso en un momento dado. Un dominio puede estar asociado con un usuario, un procedimiento o una función del sistema.

Los cambios de dominio o privilegio necesitan reglas. Por ejemplo, una solicitud puede pasar de código de usuario a código del kernel para una operación específica, sin conceder al programa control general del kernel.

De la solicitud a la decisión

SOLICITUDProceso

Solicita escribir un archivo bajo una identidad.

CONTEXTOIdentidad y objeto

Se determina quién solicita, qué recurso y qué operación.

CONTROLPolítica y permisos

Se comprueba la autorización aplicable.

RESULTADOPermitir o denegar

La operación se realiza o se rechaza; se registra si corresponde.

Caso del aula

El editor de un estudiante intenta guardar cambios en Calificaciones.csv. La sesión está autenticada, pero el dominio del proceso carece de escritura sobre ese objeto. El sistema rechaza la petición.

¿Quién protege al propio mecanismo?

El monitor de referencia es el concepto de un componente que media las solicitudes de acceso. Debe cubrir los accesos relevantes, resistir modificaciones no autorizadas y ser lo bastante pequeño y claro para poder analizarlo.

La base de cómputo confiable, o TCB (Trusted Computing Base), reúne el hardware y software del que depende la aplicación de la política. Un fallo en esta base puede comprometer las garantías del sistema.

Auditoría útil: un evento puede registrar identidad, recurso, acción, momento y resultado. Los registros también necesitan protección frente a lectura y modificación indebidas.
Ampliación: conceder y revocar derechos

La protección cambia con el tiempo. Al inscribir a una persona se le conceden permisos; cuando cambia de función, se ajustan; al retirar su acceso, se revocan. La implementación debe considerar permisos heredados, sesiones activas y accesos ya abiertos según las reglas del sistema.

Para quedarnos con lo esencial

El sistema de protección identifica el contexto, comprueba derechos, aísla recursos y aplica una decisión. Sus propios componentes forman parte de la base que debe protegerse.

Para discutir: ¿Por qué un programa normal no debería modificar las tablas de permisos?

Porque podría concederse derechos a sí mismo. Las estructuras y operaciones de administración deben estar protegidas y sujetas a autorización.
