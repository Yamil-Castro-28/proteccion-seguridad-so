Protección basada en el lenguaje

La protección también empieza al escribir un programa: el lenguaje, el compilador y el entorno de ejecución pueden imponer restricciones.

Tema 5 de 7Fuentes de este tema
Idea central

La protección basada en el lenguaje utiliza reglas del lenguaje de programación y comprobaciones del compilador o del entorno de ejecución para limitar operaciones y reducir accesos indebidos.

El sistema operativo protege procesos entre sí, pero dentro de un programa también hay datos y componentes que conviene separar. La seguridad de tipos, la encapsulación y la comprobación de límites permiten imponer restricciones más cercanas al código.

Seguridad de tipos

Restringe operaciones incompatibles con el tipo de dato. Ayuda a impedir que un valor se interprete arbitrariamente como otro.

Encapsulación

Limita el acceso a detalles internos de un componente y expone operaciones controladas mediante su interfaz.

Las comprobaciones ocurren en varias etapas

AL COMPILARReglas del lenguaje

Se detectan usos de tipos o accesos a miembros que incumplen sus reglas.

AL CARGARVerificación

En entornos como la JVM se verifica que el código intermedio respete restricciones.

AL EJECUTARControles dinámicos

Se comprueban condiciones como los límites de un arreglo y las operaciones de acceso al sistema.

Algunas propiedades pueden revisarse antes de ejecutar el programa; otras dependen de valores que se conocen durante la ejecución. Ambas clases de comprobaciones se complementan.

Ejemplo

Un arreglo con tres posiciones tiene índices 0, 1 y 2. Si el programa intenta usar el índice 5, un entorno con comprobación de límites puede rechazar la operación. Así evita tratar esa posición como memoria válida del arreglo.

Una calificación con una interfaz controlada

Este ejemplo en Java mantiene el valor como miembro privado y obliga a pasar por una operación que comprueba el rango.

class Registro {
    private int calificacion;

    public void actualizar(int valor) {
        if (valor < 0 || valor > 100) {
            throw new IllegalArgumentException();
        }
        calificacion = valor;
    }
}
  • private: restringe el acceso directo al campo según las reglas de Java.
  • int: define el tipo del valor; la regla de 0 a 100 añade una restricción del dominio escolar.
  • actualizar: concentra la comprobación para conservar un estado válido.
También hace falta autorización: este fragmento comprueba el valor, pero no identifica a quien llama al método. Una aplicación real debe comprobar qué usuario puede cambiar la calificación y proteger el registro persistente.

Un lenguaje con comprobaciones reduce ciertas clases de errores, pero la lógica del programa, las bibliotecas, el código nativo y la configuración siguen influyendo en su seguridad.

La protección basada en el lenguaje se integra con el aislamiento de procesos, los permisos del sistema y el diseño de la aplicación. Cada capa controla un aspecto distinto.

Para quedarnos con lo esencial

El lenguaje puede restringir lo que un programa expresa y el entorno puede comprobar su ejecución. Esto refuerza la protección junto con los controles del sistema operativo.

Para discutir: ¿Un campo privado impide que un usuario no autorizado cambie una nota?

Restringe el acceso en el código, pero si una operación pública modifica el campo sin comprobar permisos, todavía puede haber un fallo de autorización.
